# YL–A1 实验箱前端页面策划案 v1

日期：2026-11-10。状态：设计初稿，尚未实现。设计与策划：Codex；后续执行：swe2。

目标：以用户确认的 Linear 黑灰质感为基础，提高现有实验箱页面的视觉完成度；用带重量的短回弹和局部叠层过渡形成统一的操作手感。

## 1. 已确定的方向与交付范围

| 项目 | 决定 |
| --- | --- |
| 整体视觉 | 深色；参考 Linear 首屏的黑灰表面、细微边缘、文字层级 |
| 动效性格 | 有惯性，落位后轻轻收住；允许清楚的层次变化 |
| 关卡过渡 | 用户已确认采用叠层；用于左侧进入、切换、返回关卡 |
| 首次进入 | 现有页面内做短暂分层入场，加载与操作不等待动画 |
| 布局 | 仅微调比例、间距和分组；保留原有操作顺序 |
| 本轮目的 | 检验前端审美与执行精度，不重新定义教学流程 |
| 交付形态 | 完整版和轻量版共用同一套界面视觉与状态处理 |

以下具体色值、尺寸和时长是设计师提出的首轮实现规格，供实际页面验收时微调，不代表用户已逐项选择。暂未决定的参考不会自动成为新增功能。

## 3. 第一屏与页面比例

首屏仍然直接呈现实验箱。三维画面是主要观看区域，左侧承担选择和填写，顶部、底部工具区保持紧凑。

| 区域 | 首轮规格 | 视觉重点 |
| --- | --- | --- |
| 顶栏 | 高约 56px，左右内距 24px | YL–A1 与实验箱名称在左，版本入口与全屏在右；黑灰表面加一条细分隔线 |
| 左侧控制区 | 1440px 宽桌面下约 448px；优先保证表格可读 | 内距 24px，关卡标题与任务内容共用同一左对齐线 |
| 右侧动作工具栏 | 约 60px，可按可用宽度换行 | 保留四个动作、视角选择与重置视角；按钮之间 6–8px |
| 三维视口 | 使用右侧剩余宽度 | 保持当前镜头逻辑；视口随容器正确调整，画面不被拉伸 |
| 场景与光照区 | 视口下方约 80–88px，内容多时自然增高 | 场景选择、光线方向、保存画面按现有顺序排列 |

关卡卡片高约 64px、间距 10px。七个编号占固定宽度并对齐，标题不因编号位数变化而跳动。桌面左侧表格可用宽度低于 390px 时，优先保留现有较宽侧栏，避免为多留一点模型空间而压坏输入区。

左侧任务内容变长时在原控制区内滚动。动画仅占用左栏内部空间，右侧模型边界与工具栏保持稳定。

## 4. 配色、字与表面

### 4.1 色彩角色

先以银白主动作建立层级，色彩只承担选中、焦点和运行结果。以下为首轮色板，需在渲染画面中验证文字对比度。

| 角色 | 建议色值 | 用途 |
| --- | --- | --- |
| 页面底色 | #0D0E10 | 全页外框 |
| 控制区底色 | #15171A | 左栏、顶部与底部工具区 |
| 控件表面 | #1D2024 | 关卡卡片、次要按钮 |
| 悬停表面 | #272B30 | 可交互对象的局部提亮 |
| 输入内槽 | #111316 | 数字输入框 |
| 装饰分隔线 | #30343B | 区域及表格分隔 |
| 必要控件边界 | #6F7784 | 输入框轮廓、必要图标；实际对比度待验证 |
| 主要文字 | #F1F2F4 | 标题、关键数值 |
| 次要文字 | #A9AFB9 | 表头、说明、单位 |
| 主要按钮 | #E5E8EC，文字 #15171A | 验证并执行 |
| 选中与焦点 | #A8C5CE；选中底 #253038 | 选中标记、键盘焦点；少量使用 |
| 成功 | #9DCDB0 | 与原有成功文案配合 |
| 等待/提醒 | #E1C08A | 与原有等待或提醒状态配合 |
| 错误/停止 | #EEA29B | 与原有错误原因、停止状态配合 |

### 4.2 字体与尺寸

中文采用清晰的系统无衬线字体，沿用项目已有字体资源；Windows 优先保证微软雅黑的显示质量。数字采用等宽数字排版，保持数值变化时列宽稳定。

| 内容 | 字号/行高 | 字重 |
| --- | --- | --- |
| 页面与关卡主标题 | 24px / 32px | 600 |
| 关卡名称、重要按钮 | 14–15px / 22px | 500–600 |
| 说明、表单输入 | 14px / 22px | 400–500 |
| 表头、单位、状态 | 12–13px / 18–20px | 400–500 |
| 关卡编号 | 20px / 24px | 500 |

输入值、单位和“实际转动”等反馈保持清楚可读。表头需要两行时自然换行，避免不断缩小字体。

### 4.3 表面做法

- 关卡卡片以细边缘和轻微顶部亮边建立层次；悬停时只提亮当前卡片。
- 输入框采用略深的内槽；焦点以清楚外环表示。
- 按钮圆角约 7–8px，卡片和任务面板约 10–12px；同类组件使用一致规则。
- 稳定状态下的阴影较弱；叠层移动期间短暂加强前景面板阴影，落位后收回。
- 模型上的提示框采用有足够遮蔽度的深灰底，保证在明亮车间背景上仍能读清。字重和边缘处理与左栏统一。

## 5. 各组件的具体处理

### 5.1 关卡列表

沿用现有七张卡片、名称与顺序。卡片内由编号、名称形成两级；悬停时表面提亮，按下时轻压。选中后短暂确认当前位置，再连续进入该关任务。

编号与标题的视觉位置在进入过程中形成关联即可；如跨元素移动会导致文字缩放模糊，采用正常字号的标题淡入，不为动画牺牲中文清晰度。

### 5.2 任务面板与叠层

这是本轮的重点动效。范围为左栏内 `.lesson-picker` 和 `.lesson-task`；任务内原有“返回”和切换关卡下拉框保持可用。

| 操作 | 画面过程 | 结束状态 |
| --- | --- | --- |
| 列表点击“02 控制底座” | 点击反馈后，列表轻微缩小、后退；02 任务面板从下方少量位移进入并落到前景 | 只有任务内容可操作；标题、说明、表格和按钮清楚稳定 |
| 在下拉框从第 2 关切到第 3 关 | 返回和切换控件位置固定；原任务内容退后，新内容在同一区域前移落位 | 显示第 3 关原有数据与字段；七关顺序不变 |
| 点击返回 | 当前任务面板略向下收回，关卡列表回到前景 | 恢复关卡列表与合理的键盘焦点 |

过渡时最多显示两层；背景层只负责说明前后关系，动画结束后退出显示与可访问顺序。层间不长期堆积其他关卡。既有切关的数据处理语义保持原样。

### 5.3 数值表格

表头、输入区、行反馈使用同一网格。转动量、时间、等待仍按现有顺序排列，单位保留。输入框高约 36–38px，数值居中。

聚焦时外环立即出现，录入时不缩放表格。执行中沿用当前活动行标记，以浅色细条加背景色表示；停止行使用错误色和原有实际转动信息，其他行保持稳定。

### 5.4 按钮层级

- 当前任务中的“验证并执行”使用银白填充，成为该区域最明确的动作。
- “一键填写”及顶部机械臂搬运、云台升起、复位、爆炸拆解使用深灰填充；各自状态来自现有逻辑。
- 返回、重置视角、保存画面使用较轻的表面处理，但点击范围与名称保持清楚。
- 悬停提亮、按下压缩、松开回弹采用一套手感。键盘操作也有相应反馈。

### 5.5 下拉框、滑杆与提示

沿用原有选择控件，统一深灰表面、文字、箭头和焦点。光线方向滑杆加强当前值、轨道与把手的辨识度，把手按下时短暂放大，松开回位。镜头与光线数值的实际更新不等待装饰动画。

零件中文标签、场景标签和动作状态沿用现有内容。标签底板统一外框风格，文字与模型之间的引线继续清楚可辨。

## 6. 动效规格

下表是首轮视觉目标，不要求更换框架或安装某个动效库。连续交互时从当前可见状态接续，旧动画不排队补播。

| 场景 | 时长目标 | 幅度与节奏 |
| --- | --- | --- |
| 悬停 | 120–160ms | 背景与边缘提亮，常用按钮位置基本稳定 |
| 按下 | 80–100ms | 缩到约 98.5%；即时响应 |
| 松开 | 220–300ms | 回到原尺寸，最多一次很轻的回弹 |
| 关卡进入 | 约 380ms | 前景从下方 16–20px 到位，尺寸约 98.5%→100%；背景约 100%→98% |
| 关卡内切换 | 280–340ms | 内容少量位移和前后缩放；导航行稳定 |
| 返回 | 260–300ms | 沿进入方向反向收回，比进入略快 |
| 选中标记移动 | 180–240ms | 连续移动到当前项，不闪灭后重建视觉位置 |
| 状态变化 | 120–180ms | 文案与图标平稳替换；错误反馈即时可见 |
| 首屏入场 | 总体约 450–550ms | 顶栏、左栏、工具区依次短暂显现，区域间错开约 40–60ms |

入场只在页面首次挂载时发生。七张关卡作为一个区域出现，不逐张延迟到最后一张才能操作。模型加载按照原有过程独立进行，晚加载完成时也不重播整页入场。

“带重量”体现在较快起动、逐渐减速、一次轻微收住；回弹后文字和输入框迅速稳定。减少动态效果开启时，使用短淡入或即时状态切换，保留可见反馈。

## 7. 必须覆盖的操作状态

| 状态 | 应有表现 | 数据来源 |
| --- | --- | --- |
| 模型加载中 | 保留现有加载文案；不可用动作有清楚禁用外观 | 现有加载状态 |
| 关卡未填写完整 | 输入内容保持可读，执行按钮按原逻辑禁用 | 现有字段状态 |
| 输入不合法 | 原有错误内容清楚出现，焦点样式不被红色覆盖 | 现有入口校验 |
| 验证/运行中 | 保留原有状态文案、禁用规则及活动行；按钮尺寸稳定 | runner 和面板现有事件 |
| 动作正常完成 | 原有完成反馈平稳出现 | 实际执行结果 |
| 碰撞或运行停止 | 原有停止原因和实际转动量醒目可读 | 实际停止事件 |
| 切关过渡中 | 当前目标关卡清楚，连续操作不引起旧内容闪回或焦点落在隐藏层 | 当前选择与过渡状态 |
| 全屏或窗口变化 | 区域重新排布，视口大小更新，提示不覆盖关键按钮 | 现有全屏与尺寸变化 |

## 8. 小屏处理

- 桌面优先完成 1440×960 和 1366×768 两种画面。前者检验质感，后者检验空间紧张时的完整操作。
- 手机以 390×844 为首轮观察尺寸，保持现有控制区在前、模型在后的顺序。
- 小屏降低面板叠层位移到约 8px；过渡仍在所在区域内完成。
- 工具栏自然换行，触摸控件操作区域至少约 44px。表格在自身区域内横向滚动，页面本身不横向溢出。
- 长状态消息自然换行；用实际错误内容检查遮挡情况。

## 9. swe2 的实施顺序与接口边界

### 第一批：完整静态外观

完成整体色彩、字体层级、表面、间距和组件状态。复用现有 DOM 和类名，优先在现有 `demo-release.css` 与 `lesson-panel.css` 中作最小范围调整。用关卡列表、第 2 关、第 7 关三种真实内容查看效果。

### 第二批：叠层与回弹

围绕 `lesson-panel.js` 的进入关卡、切关、返回流程接入局部过渡。当前实现直接切换 hidden 并更新任务内容，需要协调显示时序与焦点，确保旧层不会被误操作。先让这一段完整顺畅，再统一按钮与菜单反馈。

### 第三批：状态与尺寸收尾

接入首次入场、运行反馈、小屏及减少动态效果。完成完整版与轻量版的同样操作检查。

### 完成后交给设计验收的材料

- 关卡列表、打开任务、执行中、停止反馈四个代表状态。
- 一段包含“进入第 2 关→切第 3 关→返回”的短录屏，展示实际动效。
- 常用按钮按压及连续切关的录屏或可操作本地入口。
- 变更文件清单、完成的检查及尚未解决的问题。

## 10. 验收怎么判

| 检查 | 要发现的具体问题 | 发现后怎么改 |
| --- | --- | --- |
| 真实页面对照 R1 看表面与文字 | 黑灰混成一片、边缘过亮、小字过暗 | 调整表面色阶、文字层级和边缘，不靠添加说明文案补救 |
| 三种代表内容与三个尺寸 | 第 7 关表格拥挤、工具栏溢出、提示遮挡 | 调整区域比例、换行与局部滚动 |
| 进入、切关、返回及连续切换 | 旧内容闪回、双层同时可点、切换按钮漂移、焦点丢失 | 修正过渡接续、事件归属和焦点时序 |
| 填写并执行一次及观察原有错误状态 | 动画重复触发动作、禁用失效、结果反馈不一致 | 恢复原有运行边界，动画只读取真实状态 |
| 完整版、轻量版各走主要操作 | 某一入口漏样式或动效依赖渲染模式 | 让同一 UI 改动覆盖两个入口 |
| 键盘与减少动态效果 | 焦点不可见、隐藏层仍可聚焦、减少动态后状态不可辨 | 修正焦点、隐藏层语义及反馈替代 |
| 模型正在运动时操作界面 | 大片模糊、阴影或转场导致明显卡顿 | 收窄效果区域，缩减昂贵表面效果；优先保持模型和输入响应 |

完成实现后运行 impeccable clarify 检查文案与反馈，运行 impeccable audit 检查整体。检查发现的问题需要修复并复看；本策划阶段未运行实现测试，也不承诺尚未测得的帧率。

## 11. 注意事项

- 本文是本地设计策划，当前未修改应用代码、未安装依赖、未发布新版。后续远程推送和发布另行确认。
- 保留模型资产、物理引擎、角度相对转动含义、关卡数据、既有验证语义、伪代码屏幕和所有现有功能。任务中的“验证通过”继续表示现有校验结果，不扩大为标准答案正确。
- 深色 UI 不修改三维模型受光、镜头动作或实拍车间环境，也不在渲染画布上增加全局变暗滤镜。
- 不删除现有页面文字；确有必要时先列出原文、理由与替代位置，由用户确认。品牌、必要表单标签、错误与加载反馈均保留。
- 动效参考的配色、虚构内容、营销布局、标签排序行为不随效果一起搬入。控件继续使用现有语义，不为了复用例子整体迁移框架。
- 当前示例的源码许可、版本和接入兼容性尚未逐项核实；只有执行者决定直接使用源码或新增依赖时才针对所选内容核查。视觉与行为参考不等于代码复用授权。
- 默认复用项目与浏览器已有能力。动画不修改机械臂速度、不延后运行事件、不制造假加载进度。若方案必须增加依赖或改变功能边界，应先说明具体原因再处理。
- 最终画面以本实验箱内容验收；示例中的纯黑、紫色、粉色和动效幅度不是逐项照搬要求。
